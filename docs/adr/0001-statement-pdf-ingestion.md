# 0001 — รับข้อมูลธุรกรรมจาก Statement PDF รายเดือน แทนอีเมลแจ้งเตือน

- สถานะ: ตัดสินใจแล้ว
- วันที่: 2026-08-27

## บริบท

แผนตั้งต้นคือดึงธุรกรรมจากอีเมลแจ้งเตือนรายรายการของ K PLUS: poll ทุก 5 นาที แกะ `text/plain`
ได้ ledger ที่เกือบ real-time เราวิเคราะห์ตัวอย่างจริง 3 ฉบับจนได้สัญญาของ parser ครบแล้ว

แล้วเจอข้อเท็จจริงที่ล้มแนวทางนั้นทั้งอัน: **K PLUS ไม่ส่งอีเมลแจ้ง "เงินเข้า" เลย**
ช่องทางเดียวคือ LINE OA ของ KBank ซึ่ง (ก) ดึงเข้าระบบไม่ได้ ไม่มี API ให้ third party อ่านแชท
และ (ข) แจ้งแค่ยอด ไม่บอกว่าเงินมาจากไหน

ledger ที่เห็นแต่ขาจ่ายทำให้ requirement ข้อ 1.5 (รายงาน) และ 1.6 (สรุปภาษี) เป็นไปไม่ได้
ไม่ใช่ "ไม่ครบ" แต่คือ **ผิด** — ตัวเลขรายได้ทั้งปีจะเป็นศูนย์

## การตัดสินใจ

เปลี่ยนแหล่งข้อมูลไปเป็น **ไฟล์ statement PDF รายเดือนที่ธนาคารส่งเข้าอีเมล** ไฟล์เข้ารหัสรหัสผ่าน
ผู้ใช้เป็นคนกรอกรหัสผ่านเก็บไว้ในระบบ (เข้ารหัส AES-256-GCM)

ผลที่ตามมาที่ตั้งใจรับ:

1. **ยกเลิกการแกะอีเมลแจ้งเตือนทั้งหมด** ตัวอย่าง `.eml` 3 ฉบับและงานวิเคราะห์ที่ทำไว้ ไม่ถูกใช้แล้ว
   (เก็บบันทึกการตัดสินใจไว้ในไฟล์แผนเดิม ไม่ลบ — เพื่อให้คนอ่านทีหลังเห็นว่าเคยเลือกทางไหนและทำไมถึงเลิก)
2. **poll ชั่วโมงละครั้ง** (เดิม 5 นาที) statement มาเดือนละหน ไม่รู้ว่าวันไหนของเดือน
   และแต่ละธนาคารไม่ตรงกัน แต่พอมาถึงแล้วอยากเห็นในระบบภายในชั่วโมงนั้น
3. **แยกสิ่งที่แอดมินแก้ได้ ออกจากสิ่งที่ต้อง deploy**
   - แก้ได้ในฐานข้อมูล: อีเมลผู้ส่ง, โดเมนผู้ส่ง (ตรวจ DKIM), หัวข้ออีเมล (รายเดือน / ที่ผู้ใช้ขอเอง), รูปแบบชื่อไฟล์แนบ
   - ต้อง deploy: การแกะตารางใน PDF (`parser_key` → โมดูลโค้ดต่อธนาคาร)
   เดิมตั้งใจให้ ParserTemplate ทั้งก้อนเป็น regex ในฐานข้อมูล — ตารางใน PDF แกะด้วย regex ตัวเดียวไม่ไหว
4. **เดิมเลือก launch ด้วย KBank ธนาคารเดียว** — ถูกแทนที่ด้วยการตัดสินใจวันที่ 2026-08-30 ด้านล่าง
5. **ถอดรหัสในหน่วยความจำเท่านั้น** `qpdf --password-file=- --decrypt in.pdf - | pdftotext -layout - -`
   รหัสผ่านผ่าน stdin ไม่ผ่าน argv (argv โผล่ใน process list) และ PDF ที่ถอดรหัสแล้วไม่เคยลงดิสก์
   ต้นฉบับที่ยัง**เข้ารหัสอยู่**คือ artifact ที่เก็บไว้ re-parse ได้
6. **checksum เป็นด่าน ไม่ใช่เทส** `ยอดยกมา + เครดิต − เดบิต == ยอดยกไป` ไม่ผ่านคือไม่เขียนสักแถว
   ทั้ง statement import อยู่ใน DB transaction เดียว
7. **`txn.txn_date` คือวันที่ในบรรทัดของ statement ไม่ใช่วันที่อีเมลมาถึง**
   statement เดือนมกราคมมาถึงต้นกุมภาพันธ์ ถ้าประทับวันที่อีเมล ปีภาษีเพี้ยนทั้งชุด

## สิ่งที่แก้ระหว่างลงมือทำ

**การจับคู่เลขบัญชีที่ถูกปิดบัง — แผนเขียนว่า "เทียบแบบ suffix" ซึ่งผิด**

K PLUS ปิดบังเลขบัญชีเป็น `xxx-x-x6231-x` คือ **ปิดหลักท้ายด้วย** ตัวเลขที่เห็น (`6231`)
จึงไม่ใช่ท้ายของเลขจริง (`1234562317`) เทียบแบบ suffix จะไม่ match บัญชีที่ถูกต้องเลย

กฎที่ใช้จริง (`src/account-match.ts`): ถ้าความยาว (นับเฉพาะตัวเลขและ `x`) เท่ากัน → **เทียบตามตำแหน่ง**
เฉพาะหลักที่เปิดให้เห็น ถ้าความยาวไม่เท่ากัน (เช่น `****1234`) → ถอยไปเทียบท้าย และต้องเห็นอย่างน้อย 4 หลัก
**เข้าได้มากกว่า 1 บัญชี = ปฏิเสธ** ไม่เดา

รูปแบบการปิดบังใน statement จริงยังต้องยืนยันอีกครั้งเมื่อได้ตัวอย่าง PDF

## ผลที่ตามมา

**ยอมแลก:** ledger ช้าได้ถึง ~35 วัน (statement เดือนมกราคมอาจมาถึงต้นกุมภาพันธ์)
ผู้ใช้รับทราบและยอมรับแล้ว — ความครบถ้วนสำคัญกว่าความสด

**ได้เพิ่ม:** ยอดคงเหลือต่อบรรทัด ทำให้ยืนยันความถูกต้องได้ทั้งชุด ซึ่งอีเมลแจ้งเตือนให้ไม่ได้

**ความเสี่ยงที่ยังตอบไม่ได้จนกว่าจะเห็นตัวอย่าง PDF จริง:** PDF ไม่มี ToUnicode CMap (ข้อความไทยออกมาเป็นขยะ),
statement เป็นภาพสแกน (ต้อง OCR — งานคนละขนาด), ไม่มีคอลัมน์ยอดคงเหลือต่อบรรทัด (unique key ของ `txn` พังทั้งอัน),
ตารางข้ามหน้า, ปี พ.ศ. ในตาราง

Slice 2 จบด้วยการ dump ข้อความที่สกัดได้ลง `statement.error_detail` เพื่อให้รู้ว่าข้อไหนเกิดจริง **ก่อน**
ลงมือเขียน parser (ข้อความนี้ต้องตัดความยาวและล้างทิ้งเมื่อ parser เสร็จ — เป็นประวัติธุรกรรมเต็มที่ถูก backup ไปด้วย)

## การตัดสินใจเพิ่มเติม — 2026-08-30

เปลี่ยนธนาคารแรกจาก KBank เป็น **SCB** เพราะมี statement จริงครบทั้งแบบรายเดือนและแบบขอย้อนหลังให้ยืนยัน parser ได้
SCB ส่งไฟล์ด้วย MIME `application/octet-stream` และอีเมลย้อนหลังหนึ่งฉบับแนบ PDF หลายเดือน จึงต้อง:

- ยอมรับ octet-stream เฉพาะชื่อที่ตรง pattern และตรวจ magic bytes `%PDF-` ก่อนบันทึก
- ประมวลผลทุก attachment แยกกัน ไม่ใช่เลือกไฟล์แรก
- dedup statement ด้วย `(bank_account_id, gmail_message_id, gmail_attachment_id)`
- รองรับไฟล์รายเดือนและย้อนหลังของเดือนเดียวกัน โดย dedup รายการที่ unique key ของ `txn`
